# Entity relationships

Order 1:N OrderLine (each line has one SKU); Order 1:N Shipment. Shipment M:N OrderLine via ShipmentLine records allocated quantities and permits split fulfillment. FulfillmentNode M:N SKU via Inventory; node 1:N WarehouseCapacity by date. InventoryTransaction references a node/SKU stock position and optionally order, line and shipment; it is an append-only stock event ledger. Carrier M:N ServiceLevel through CarrierServiceLevel. ServiceLevel M:N Zone via ServiceZone. FulfillmentNode M:N Zone via NodeServiceZone. Shipment 1:N TrackingEvent, unique by shipment and event sequence. Order 1:N OrderDeliveryPromise revisions; Shipment 1:N ShipmentDeliveryPromise revisions, in separate tables to avoid nullable polymorphic references. Holidays use calendar code/date composite key; nodes identify their calendar. All references use declared foreign keys. See data_dictionary.md for columns and business_rules.md for rule semantics.
